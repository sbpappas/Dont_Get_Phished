# PhishGuard

An explainable phishing URL & website analyzer. Give it a URL and it tells
you not just *whether* it looks like phishing, but *why* — a plain-language
list of the specific red flags it found, alongside a probability from a
machine learning model trained on a real, published phishing dataset.

Available as a **CLI** and a **local web dashboard**.

```
$ phishguard analyze http://paypal-secure-login.xyz/verify/account --offline
URL:     http://paypal-secure-login.xyz/verify/account
Domain:  paypal-secure-login.xyz
Verdict: Likely Phishing  (score 60/100)
  Heuristic score only (ML unavailable this run): 60/100
  (Live page was not fetched: offline mode)

Findings:
  [!!!] (critical +30) Domain contains the brand name 'paypal' but is not
                        'paypal.com' (registered domain is
                        'paypal-secure-login.xyz') -- classic impersonation
                        pattern.
  [!  ] (medium   +10) Top-level domain '.xyz' is frequently abused for
                        low-cost, throwaway phishing domains.
  [!  ] (medium   +10) URL does not use HTTPS.
  [!  ] (medium   +10) URL contains multiple credential/urgency-themed
                        keywords: login, verify, secure, account, update.
```

(Drop `--offline` on a real run and the ML model's probability is blended in
too — see [`examples/sample_output.json`](examples/sample_output.json) for a
full JSON report.)

## Why this exists

Most "is this phishing" tools give you a single opaque number. PhishGuard
is built around the opposite idea: **the explanation is the product.** A
risk score a user can't interrogate doesn't help them decide whether to
trust their bank's password reset email — a ranked list of concrete,
named reasons does. Every finding below is one a non-technical reader can
act on.

## How it works

PhishGuard blends two independent signals into one score, and always shows
both:

1. **A rule-based heuristics engine** (`phishguard/heuristics.py`) —
   ~20 explainable checks across the URL string, the domain's registration
   and DNS/TLS posture, and (when live-fetched) the page's own HTML. Each
   check is a named `Finding` with a severity and point value, so the
   report reads like an audit, not a verdict from a black box.

2. **A machine learning classifier** — a `RandomForestClassifier` trained
   on **58,645 real labeled URLs** from the phishing dataset published by
   Vrban&#269;i&#269;, Zelenko & Podgorelec,
   ["Datasets for phishing websites detection"](https://doi.org/10.1016/j.dib.2020.106438)
   (*Data in Brief*, 2020). PhishGuard reimplements 38 of that paper's
   feature definitions (see `phishguard/feature_schema.py`) so the exact
   same feature vector can be computed live from an arbitrary URL at
   inference time — no dependency on the dataset's precomputed columns
   at runtime.

   | Metric | Value |
   |---|---|
   | Test accuracy | 94% |
   | ROC AUC | 0.985 |
   | Train / test rows | 46,916 / 11,729 |

   Full metrics (precision/recall, feature importances) are in
   [`models/metadata.json`](models/metadata.json), regenerated by
   `scripts/train_model.py`.

The final score is `0.5 * heuristic_score + 0.5 * (ML probability * 100)`.
If live network access isn't available (offline mode, or the site is
unreachable), PhishGuard falls back to heuristics alone and says so
explicitly in the report rather than silently degrading.

### Feature tiers

| Tier | Examples | Needs network? |
|---|---|---|
| **Lexical** (`url_features.py`) | URL/domain/path length, special-character counts, IP-as-hostname, punycode, URL shorteners | No |
| **Network/host** (`network_features.py`) | DNS A/MX/NS/SPF records, WHOIS domain age & expiration, TLS certificate validity, HTTP response time & redirect count | Yes |
| **Content** (`content_features.py`) | Password fields posting to a foreign domain, favicon/title brand mismatches, iframes, meta-refresh redirects | Yes (HTML fetch) |
| **Brand impersonation** (`heuristics.py`) | Substring + fuzzy (`difflib`) matching against ~35 commonly spoofed brands (PayPal, banks, shippers, IRS, exchanges, ...) | No |

### Safety by design

The live fetcher (`phishguard/fetcher.py`) is read-only and deliberately
constrained:

- **GET only** — never submits a form, never executes JavaScript.
- **SSRF guard** — resolves the hostname first and refuses to connect if it
  points at a loopback, private, link-local, or otherwise internal address.
- **Timeouts everywhere** (HTTP, DNS, WHOIS, TLS) so one unresponsive host
  can't hang an analysis; every network feature degrades to an explicit
  "unknown" (`-1`) sentinel rather than crashing.
- **Response size cap** to avoid memory exhaustion on a malicious or huge
  page.
- Identifies itself with a descriptive User-Agent rather than spoofing a
  browser.

## Installation

```bash
git clone <this-repo>
cd phishing
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Train (or retrain) the model — the dataset is included in `data/`, so this
works offline:

```bash
python scripts/train_model.py
```

This writes `models/model.joblib` and `models/metadata.json`. If no model
file is present, PhishGuard still runs fine — it just reports the
heuristic score alone.

## Usage

### CLI

```bash
# Full live analysis (DNS, WHOIS, TLS, page content)
python3 -m phishguard analyze https://example.com/login

# URL structure only, no network calls
python3 -m phishguard analyze https://example.com/login --offline

# Machine-readable output
python3 -m phishguard analyze https://example.com/login --json

# Batch mode: one URL per line
python3 -m phishguard batch urls.txt
python3 -m phishguard batch urls.txt --json
```

### Web dashboard

```bash
FLASK_APP=phishguard.webapp.app python3 -m flask run
```

Then open `http://127.0.0.1:5000`, paste a URL, and read the report —
verdict badge, blended score, and the full findings list with severity
tags.

### As a library

```python
from phishguard.analyzer import analyze

result = analyze("https://example.com/login")
print(result.verdict, result.score)
for finding in result.findings:
    print(finding.severity, finding.message)
```

## Project layout

```
phishguard/
  feature_schema.py    # canonical FEATURE_ORDER shared by training + inference
  url_features.py       # lexical features (offline)
  network_features.py   # DNS / WHOIS / TLS features (live)
  content_features.py   # HTML page analysis (live)
  fetcher.py             # safe, guarded HTTP fetch
  heuristics.py           # explainable rule engine
  ml_model.py              # trained model loader/predictor
  analyzer.py               # orchestrates all of the above into a Result
  report.py                  # text/JSON rendering for the CLI
  cli.py                       # argparse CLI
  webapp/                       # Flask dashboard
data/
  dataset_small.csv    # training data (Vrbancic et al., 2020)
  brands.json            # commonly impersonated brands -> real domain
  suspicious_keywords.txt
models/
  model.joblib          # trained RandomForestClassifier
  metadata.json           # accuracy, ROC AUC, feature importances
scripts/train_model.py    # retrain from data/dataset_small.csv
tests/                       # pytest suite (offline, deterministic)
```

## Testing

```bash
pip install -r requirements-dev.txt
pytest
```

All tests run fully offline against the heuristics/lexical layers, so they're
deterministic and fast (~1s).

## Limitations & disclaimer

This is an educational portfolio project, not a production security
product. It is not a replacement for browser phishing protection, email
security gateways, or professional threat intelligence. In particular:

- The heuristic thresholds and point values are hand-tuned, not
  statistically calibrated.
- WHOIS data availability varies a lot by registrar/TLD and is sometimes
  redacted by privacy services, which shows up as "unknown" rather than a
  hard signal.
- The brand list covers ~35 commonly targeted organizations; anything
  outside it relies on the generic lexical/network/content heuristics.

**Never enter credentials on a page PhishGuard flags as Suspicious or
Likely Phishing** — and don't treat a "Likely Safe" verdict as a guarantee,
either.
